# Request / Response 说明

Request：前端发送给后端的查询条件。

Response：后端根据查询条件处理后，返回给前端展示的数据。

核心理解：

> Request 不是“我要哪些结果”，而是“我用什么条件去查”。
> Response 才是“后端查完以后给我的结果”。

## 7.1 首页 KPI 数据接口

### 1. 接口目标

前端打开首页时，自动请求首页 KPI 数据，用于展示首页顶部的四个指标卡片：

- 总销售额
- 总订单量
- 客单价
- 退款率

### 2. Request

当前阶段前端打开页面后自动请求，不需要用户手动输入筛选条件。

| 字段 | 是否必填 | 说明 | 默认值 |
| --- | --- | --- | --- |
| 暂无 | 否 | 页面打开后自动请求首页 KPI 数据 | 默认查询本月数据 |

说明：

- 当前接口默认查询本月数据。
- 后续如果页面增加筛选条件，可以再扩展开始日期、结束日期、店铺、品类等字段。

### 3. Response

后端返回 `kpiList`，表示 KPI 指标列表。

| 字段 | 说明 |
| --- | --- |
| kpiList | KPI 指标列表 |

`kpiList` 中每一项包含以下字段：

| 字段 | 中文含义 | 说明 |
| --- | --- | --- |
| metricKey | 指标标识 | 给前端识别当前指标是谁，例如 totalSales |
| title | 指标名称 | 展示给用户看的名称，例如总销售额 |
| currentValue | 当前值 | 后端计算后的原始数值 |
| unit | 单位 | 例如元、单、% |
| compareType | 对比类型 | 同比或环比 |
| changeRate | 变化率 | 数字，例如 12.5 或 -0.5 |
| betterDirection | 趋势好坏方向 | up 表示越高越好，down 表示越低越好 |
| description | 补充说明 | 展示指标补充信息，例如目标完成率 |

### 4. KPI 指标范围

| metricKey | title | unit | betterDirection |
| --- | --- | --- | --- |
| totalSales | 总销售额 | 元 | up |
| totalOrders | 总订单量 | 单 | up |
| avgOrderAmount | 客单价 | 元 | up |
| refundRate | 退款率 | % | down |

### 5. 指标计算口径

| 指标 | 计算口径 |
| --- | --- |
| 总销售额 | 本月有效订单的实付金额合计 |
| 总订单量 | 本月有效订单数量 |
| 客单价 | 总销售额 / 总订单量 |
| 退款率 | 本月退款订单量 / 本月有效订单数量 |

说明：

- 有效订单不包含已取消订单。
- 未支付订单是否计入，需要后续根据业务规则确认。
- 如果总订单量为 0，客单价返回 0。
- 如果有效订单数量为 0，退款率返回 0。

### 6. 业务说明

首页 KPI 接口只查询已经准备好的业务数据。

Excel 文件监听、清洗和入库属于后台数据准备流程，不在用户打开首页时执行。

页面访问时的职责是：

- 前端打开首页后自动请求首页 KPI 接口。
- 后端按默认时间范围查询已准备好的业务数据。
- 后端根据统一指标口径计算 KPI。
- 后端组装 `kpiList` 返回给前端。
- 前端根据 `metricKey`、`currentValue`、`unit`、`changeRate`、`betterDirection` 展示卡片、颜色、箭头和格式化结果。

### 7. 异常情况

| 场景 | 处理方式 |
| --- | --- |
| 本月没有订单数据 | 接口正常返回，四个 KPI 的 currentValue 返回 0 |
| 总订单量为 0 | 客单价返回 0，避免除零错误 |
| 有效订单数量为 0 | 退款率返回 0，避免除零错误 |
| 数据查询失败 | 返回查询失败信息，前端展示“数据获取失败” |
