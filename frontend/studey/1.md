## 2. 项目背景

企业在日常经营过程中会产生大量业务数据，例如订单数据、商品数据、销售数据、退款数据、区域数据、店铺数据等。当前业务数据虽然已经存在于企业内部系统或数据库中，但在管理和分析过程中仍然存在以下问题：

1. 数据分散在不同业务系统中，查询入口不统一。
2. 经营数据依赖人工统计或固定报表，响应慢、不灵活。
3. 管理层需要快速查看特定时间段、特定业务条件下的销售、订单、退款、商品、区域等数据。
4. 业务人员需要通过订单号、商品、区域、时间等条件快速查询明细数据。
5. 缺少统一的数据指标体系，导致销售额、订单量、客单价、退款率、同比、环比等指标口径不一致。
6. 缺少统一的可视化看板，无法直观展示经营趋势、爆品排行、区域表现和异常变化。
7. 缺少对用户搜索关键词、浏览次数和外部趋势数据的统一分析，无法判断哪些关键词具有更高运营价值。
8. 缺少权限控制、操作日志和数据范围控制，难以满足企业内部数据安全要求。

因此，需要建设一套面向企业经营分析的数据统计管理平台。系统不提供数据导入功能，而是基于已有业务数据库、数据仓库或后端接口进行数据查询、统计、分析和展示，帮助企业将已有业务数据转化为可查询、可分析、可辅助决策的数据资产。

## 3. 项目建设目标

### 3.1 业务目标

1. 建立统一的数据查询和分析入口，减少人工统计和跨系统查询成本。
2. 建立统一的指标体系，保证销售额、订单量、客单价、退款率、同比、环比等核心指标口径一致。
3. 为管理层提供经营总览看板，快速了解企业销售、订单、商品、区域和时间趋势。
4. 为运营人员提供多维分析能力，支持按品类、区域、时间、店铺、商品等维度下钻分析。
5. 为运营人员提供关键词洞察能力，展示用户搜索关键词带来的浏览次数、eHunt 趋势变化和推荐关键词。
6. 为业务人员提供订单查询、全局搜索和智能问答能力，降低数据查询门槛。
7. 建立企业级权限、日志、监控和性能保障机制，支撑多部门、多角色协同使用。

### 3.2 技术目标

1. 采用前后端分离架构，前端负责页面交互和图表展示，后端负责数据查询、指标计算和接口服务。
2. 采用微服务架构，将权限认证、指标聚合、查询分析、搜索问答、日志监控等能力解耦。
3. 支持对接已有业务数据库、数据仓库或内部 API。
4. 支持接入客户提供的关键词浏览统计 Excel 数据结果，并在后台转为标准数据源使用，不提供前端导入功能。
5. 支持接入 eHunt 采集数据，用于关键词趋势、增长率和推荐关键词分析。
6. 核心查询接口 P95 响应时间控制在 500ms 以内。
7. 高频指标支持缓存、预聚合或宽表设计，提升看板响应速度。
8. 系统具备可观测能力，包括接口日志、错误日志、性能监控和告警。

| 角色 | 主要职责 | 权限范围 |
| --- | --- | --- |
| 超级管理员 | 系统初始化、用户管理、角色管理、系统配置 | 全部权限 |
| 系统管理员 | 维护菜单、角色、权限、系统参数 | 除超级管理员配置外的大部分管理权限 |
| 运营人员 | 查看看板、分析商品、区域、时间趋势，导出图表 | 业务分析权限 |
| 业务人员 | 查询订单、搜索数据、查看授权范围内的分析结果 | 查询与基础查看权限 |

权限控制要求：

1. 支持账号密码登录。
2. 支持基于角色的菜单权限控制。
3. 支持按钮级权限控制，例如查询、导出、查看详情、系统配置。
4. 支持数据范围权限控制，例如按部门、区域、店铺、业务线限制可见数据。
5. 所有关键操作需要记录审计日志，包括登录、查询、导出、权限变更等。

## 6. 总体架构设计

系统建议采用“四层业务能力 + 微服务支撑”的企业级架构。

### 6.1 第一层：数据源对接层

负责解决系统从哪里获取业务数据的问题。

本项目不提供数据导入能力，数据来源应由企业已有系统或数据库提供。

支持的数据来源：

1. 已有业务数据库。
2. 企业数据仓库。
3. 内部业务系统 API。
4. 已建设的数据中台接口。
5. 客户提供的关键词浏览统计数据。
6. eHunt 关键词趋势与增长率数据。
7. 后续可扩展第三方业务系统接口。

数据源对接要求：

1. 数据源连接信息需统一配置和管理。
2. 系统原则上以只读方式访问业务数据。
3. 业务查询需通过后端服务封装，前端不得直接访问数据库。
4. 不同数据源字段需要在后端统一转换为标准数据模型。
5. 数据源异常时，前端页面需展示明确的异常提示。
6. 关键词浏览统计数据需统一转换为关键词、日期、浏览次数、搜索次数、品类、来源等标准字段。
7. eHunt 数据需统一转换为关键词、趋势值、增长率、热度、平台来源、采集时间等标准字段。

### 6.2 第二层：数据标准层

负责解决不同系统之间字段、状态、口径不统一的问题。

核心能力：

1. 标准字段模型。
2. 订单状态统一。
3. 退款状态统一。
4. 商品品类统一。
5. 区域层级统一。
6. 店铺和业务线统一。
7. 金额、数量、时间等字段格式统一。
8. 数据权限字段统一。
9. 关键词名称统一，例如去除首尾空格、统一大小写、合并同义词或近义词。
10. eHunt 关键词趋势和内部关键词浏览数据需要建立关联关系。

处理原则：

1. 不修改原始业务系统数据。
2. 通过查询视图、数据宽表、聚合表或接口适配层完成标准化。
3. 指标统计使用统一标准模型，避免各页面单独计算造成口径不一致。
4. 对无法识别或缺失的关键字段，需要在接口返回中给出明确提示或兜底展示。

### 6.3 第三层：指标层

负责解决业务到底看什么、如何统一统计口径的问题。

核心指标：

1. 总销售额。
2. 总订单量。
3. 客单价。
4. 退款金额。
5. 退款率。
6. 同比增长率。
7. 环比增长率。
8. Top10 热销商品。
9. Top10 高退款商品。
10. 区域销售排名。
11. 品类销售占比。
12. 月度销售趋势。
13. 月度订单趋势。
14. 销量与退款率趋势对比。
15. 关键词搜索浏览次数。
16. 关键词浏览次数排名。
17. eHunt 关键词趋势。
18. eHunt 关键词增长率。
19. 推荐关键词。

指标口径示例：

| 指标 | 计算规则 |
| --- | --- |
| 总销售额 | 指定筛选条件下的实付金额合计 |
| 总订单量 | 指定筛选条件下的有效订单数量 |
| 客单价 | 总销售额 / 总订单量 |
| 退款率 | 退款订单量 / 总订单量 |
| 同比增长率 | 本期数据与去年同期数据的增长比例 |
| 环比增长率 | 本期数据与上一周期数据的增长比例 |
| Top10 热销商品 | 按销售额或销量倒序取前 10 名商品 |
| 关键词搜索浏览次数 | 用户通过某个关键词进入浏览行为的次数，例如搜索“玉”后产生的浏览次数 |
| eHunt 关键词增长率 | 当前周期关键词热度与上一周期关键词热度的增长比例 |
| 推荐关键词 | 综合内部浏览次数、eHunt 趋势、增长率和业务相关性后生成的关键词推荐 |

### 6.4 第四层：展示层

负责解决数据如何被用户高效查看、分析和使用的问题。

核心页面：

1. 首页经营看板。
2. 商品分析页。
3. 区域分析页。
4. 时间趋势页。
5. 关键词洞察页。
6. 订单查询页。
7. 全局搜索页。
8. 智能问答页。
9. 用户权限管理页。
10. 系统配置页。
11. 操作日志页。

## 7. 功能需求

### 7.1 首页经营看板

首页用于管理层快速查看企业经营概况，要求打开后即可看到核心经营指标和趋势。

页面模块：

1. 顶部筛选区。
   - 时间范围选择。
   - 店铺选择。
   - 业务线选择。
   - 区域选择。
   - 品类选择。
   - 重置和查询按钮。

2. KPI 指标卡片。
   - 总销售额。
   - 总订单量。
   - 客单价。
   - 退款率。
   - 同比涨跌幅。
   - 环比涨跌幅。

展示要求：

1. 同比和环比使用绿色/红色箭头展示涨跌。
2. 指标卡需展示当前值、变化率和对比周期。
3. 金额需要展示千分位和货币单位。
4. 空数据时展示明确的空状态。
5. 接口异常时展示错误提示，并支持重新查询。

3. Top10 商品分析图。
   - 支持展示 Top10 热销商品排行榜。
   - 支持展示帕累托图，用于体现二八定律。
   - 支持按销售额或销量切换排序。
   - 支持点击饼图扇区或 Top10 商品排行行。
   - 点击某个商品后，该商品作为当前选中商品，右侧关键词洞察模块和下方高增长关键词模块需要同步刷新。
   - 选中的商品需要有明显高亮状态，便于用户知道当前右侧数据对应哪个商品。

4. 月度趋势图。
   - 展示最近 12 个月销售额趋势。
   - 支持今年与去年同期对比。
   - 支持销量与退款率双轴折线图。
   - 支持鼠标悬浮查看具体数值。

5. 关键词搜索浏览洞察模块。
   - 原“数据质量雷达”区域调整为“关键词搜索浏览洞察”。
   - 展示当前选中商品对应的用户搜索关键词和浏览次数。
   - 支持按关键词查询，例如当前选中商品下输入或选择“玉”，展示该商品下该关键词对应的浏览次数。
   - 关键词浏览次数以客户提供的关键词统计 Excel 数据为基础，由后台标准化后提供给前端展示。
   - Excel 关键词数据需要包含商品与关键词的对应关系，例如商品名称、商品编码、关键词、搜索次数、浏览次数、增长率等字段。
   - 支持展示当前商品下的 Top 关键词排行，包括关键词、浏览次数、占比、环比变化。
   - 支持按时间范围、店铺、业务线、品类筛选关键词浏览数据。
   - 支持关键词为空时展示推荐关键词或热门关键词兜底。
   - 当用户点击左侧 Top10 商品中的“USB-C 充电器 35W”时，右侧应展示该商品在 Excel 中对应的搜索关键词，例如“USB-C 充电器”“35W 快充头”“苹果充电器”“PD 快充”等。

6. eHunt 趋势与高增长关键词模块。
   - 放置在关键词搜索浏览洞察模块下方，用于填充原页面空白区域。
   - 展示 eHunt 抓取或采集到的关键词趋势数据。
   - 支持展示关键词热度趋势折线图。
   - 趋势折线图需要跟随右侧“产品高增长关键词”列表展示，右侧列表中有哪些高增长关键词，左侧趋势图就展示对应关键词的趋势曲线。
   - 支持展示当前选中商品下增长率较高的关键词列表。
   - 高增长关键词需要跟随 Top10 商品选择同步切换，与右侧关键词搜索浏览洞察使用同一个当前商品上下文。
   - 列表字段包括关键词、搜索次数、浏览次数、增长率、趋势方向、采集时间。
   - 增长率较高的关键词需突出展示，便于运营人员快速发现当前商品的机会词。
   - 支持按增长率、热度、浏览次数排序。

7. 推荐关键词模块。
   - 放置在 eHunt 趋势与高增长关键词模块下方。
   - 推荐关键词需要跟随当前选中商品同步切换，与关键词搜索浏览洞察、高增长关键词使用同一个当前商品上下文。
   - 基于当前商品的内部关键词浏览次数、eHunt 热度趋势、增长率和业务相关性生成推荐关键词。
   - 推荐结果需展示关键词、推荐理由、内部浏览次数、eHunt 增长率和建议使用场景。
   - 推荐理由示例：内部浏览次数高、外部趋势增长快、与当前品类相关、近期热度上升明显。
   - 推荐关键词支持点击后联动刷新关键词浏览次数和 eHunt 趋势图。
   - 当用户点击左侧 Top10 商品中的“USB-C 充电器 35W”时，推荐关键词应展示该商品对应的词，例如“35W 快充头”“PD 快充”“USB-C 充电器”等。

8. 数据更新时间。
   - 首页需要展示最近一次数据更新时间。
   - 当数据源异常或接口异常时，需要给出明显提示。

### 7.2 商品分析页

用于分析商品维度的销售表现和经营质量。

功能要求：

1. 支持按时间、店铺、业务线、品类、商品名称、商品编码筛选。
2. 支持查看商品销售额、销量、订单量、退款率、客单价。
3. 支持 Top10 热销商品排行。
4. 支持 Top10 高退款商品排行。
5. 支持商品品类销售占比图。
6. 支持商品明细表格分页查询。
7. 支持表格按销售额、销量、退款率排序。
8. 支持导出商品分析结果。
9. 支持图表导出为 PNG。

### 7.3 区域分析页

用于分析不同区域、城市、门店的销售表现。

功能要求：

1. 支持按区域、省份、城市、门店下钻分析。
2. 支持查看区域销售额、订单量、客单价、退款率。
3. 支持区域销售排名。
4. 支持区域热力图。
5. 支持区域销售趋势对比。
6. 支持导出区域分析数据。

### 7.4 时间趋势页

用于查看企业经营数据在不同时间周期下的变化趋势。

功能要求：

1. 支持按日、周、月、季度、年切换统计周期。
2. 支持销售额趋势分析。
3. 支持订单量趋势分析。
4. 支持退款率趋势分析。
5. 支持同比曲线和环比曲线。
6. 支持多指标同时对比。
7. 支持导出趋势图为 PNG。

### 7.5 关键词洞察页

用于分析用户搜索关键词带来的浏览行为，并结合 eHunt 外部趋势数据辅助运营选词。

页面定位：

1. 帮助运营人员判断用户实际在搜索什么。
2. 帮助运营人员查看某个关键词带来的浏览次数。
3. 帮助运营人员发现 eHunt 趋势增长较快的关键词。
4. 帮助运营人员获得可用于标题、标签、投放、选品分析的推荐关键词。

筛选条件：

1. 关键词。
2. 时间范围。
3. 店铺。
4. 业务线。
5. 品类。
6. 商品名称或商品编码。
7. 来源类型，例如内部搜索数据、eHunt 数据。

页面模块：

1. 关键词概览卡片。
   - 展示当前商品。
   - 展示当前关键词。
   - 展示浏览次数。
   - 展示搜索次数。
   - 展示浏览占比。
   - 展示环比增长率。

2. 关键词浏览次数排行。
   - 展示当前商品下用户搜索关键词后产生的浏览次数排名。
   - 支持搜索指定关键词，例如“玉”。
   - 支持按浏览次数、搜索次数、环比增长率排序。
   - 支持点击关键词查看详情。
   - 支持从首页 Top10 商品跳转或联动带入当前商品。

3. eHunt 关键词趋势。
   - 展示 eHunt 采集到的关键词趋势折线图。
   - 支持按日、周、月切换趋势周期。
   - 支持对比多个关键词的趋势变化。
   - 支持展示当前热度、上期热度和增长率。

4. 高增长关键词列表。
   - 展示当前商品下增长率较高的关键词。
   - 支持按增长率倒序展示。
   - 支持标记高潜力关键词。
   - 支持与内部浏览次数进行对比，判断外部热度与内部需求是否匹配。
   - 当商品切换时，高增长关键词列表必须同步切换，不能继续展示上一商品的数据。

5. 推荐关键词。
   - 展示系统推荐的关键词列表。
   - 推荐依据包括内部浏览次数、eHunt 热度、eHunt 增长率、品类相关性。
   - 展示推荐理由，避免只给出关键词而无法解释。
   - 支持点击推荐关键词后联动查询该关键词详情。

数据口径：

| 字段 | 说明 |
| --- | --- |
| 商品名称 | 关键词所属商品名称 |
| 商品编码 | 关键词所属商品编码，用于准确关联商品 |
| 关键词 | 用户搜索词或 eHunt 采集词 |
| 浏览次数 | 用户搜索该关键词后产生的浏览行为次数 |
| 搜索次数 | 用户输入并搜索该关键词的次数 |

| eHunt 热度 | eHunt 采集到的关键词热度值 |
| eHunt 增长率 | 当前周期热度相对上一周期热度的增长比例 |
| 推荐分 | 综合内部浏览、外部趋势、增长率、业务相关性计算的推荐排序分 |

## 8. 数据处理与查询流程

### 8.1 标准查询流程

1. 用户登录系统。
2. 后端识别用户角色和数据权限。
3. 前端发起查询请求。
4. 网关服务完成认证和鉴权。
5. 查询分析服务解析筛选条件。
6. 指标服务根据统一口径计算指标。
7. 数据权限条件自动拼接到查询逻辑中。
8. 查询缓存、预聚合表、宽表或业务数据库。
9. 后端返回统一格式数据。
10. 前端渲染 KPI、图表或明细表格。
11. 系统记录查询日志和性能耗时。

### 8.2 指标计算流程

1. 接收时间、店铺、区域、品类、业务线等筛选条件。
2. 校验用户是否有对应数据访问权限。
3. 根据指标口径选择对应聚合逻辑。
4. 优先查询指标汇总表或缓存数据。
5. 无汇总数据时查询明细表并实时聚合。
6. 返回指标值、同比值、环比值和变化趋势。

### 8.3 数据标准化流程

1. 从已有业务数据库、数据仓库或 API 获取业务数据。
2. 通过适配层将不同来源字段转换为统一标准字段。
3. 统一订单状态、退款状态、商品品类、区域层级等枚举值。
4. 为查询和统计提供统一的数据视图或接口模型。
5. 对缺失或异常字段进行兜底处理，并在日志中记录。

### 8.4 关键词洞察计算流程

1. 获取客户提供的关键词浏览统计数据，并由后台转换为标准关键词统计表。
2. 关键词统计数据需要保留商品维度，至少包含商品名称或商品编码、关键词、搜索次数、浏览次数、增长率、统计日期等字段。
3. 对关键词进行标准化处理，包括去除空格、统一大小写、合并同义词、处理特殊符号。
4. 按商品、关键词、日期、店铺、业务线、品类聚合浏览次数和搜索次数。
5. 首页 Top10 商品列表与关键词统计表通过商品名称或商品编码建立关联。
6. 当用户点击 Top10 商品中的某个商品时，系统将该商品设置为当前商品。
7. 当前商品变化后，右侧关键词浏览洞察模块需要查询并展示该商品对应的关键词浏览数据。
8. 当前商品变化后，下方高增长关键词模块需要同步查询并展示该商品对应的增长率较高关键词。
9. 当用户查询某个关键词时，例如当前商品下的“USB-C 充电器”，系统返回该商品下该关键词在指定条件下的浏览次数、搜索次数、占比和变化趋势。
10. 获取 eHunt 采集到的关键词热度和趋势数据。
11. 按商品和关键词将内部浏览数据与 eHunt 外部趋势数据进行匹配。
12. 计算 eHunt 或内部关键词增长率，筛选当前商品下增长率较高的关键词。
13. 根据当前商品的内部浏览次数、eHunt 热度、eHunt 增长率、品类相关性生成推荐关键词。
14. 前端按照“当前商品、关键词浏览次数、eHunt 趋势、高增长关键词、推荐关键词”的结构展示。

### 8.5 推荐关键词生成规则

推荐关键词需要避免只按单一指标排序，建议采用综合评分。

推荐分计算维度：

1. 内部浏览次数：浏览次数越高，说明用户已有明确兴趣。
2. 内部搜索次数：搜索次数越高，说明用户主动需求越明显。
3. eHunt 热度：外部平台热度越高，说明市场关注度越高。
4. eHunt 增长率：增长率越高，说明关键词近期上升趋势越明显。
5. 品类相关性：关键词与当前商品品类越匹配，推荐优先级越高。
6. 去重与过滤：排除无意义词、敏感词、重复词和与业务无关的词。

推荐结果展示要求：

1. 推荐关键词。
2. 推荐分。
3. 推荐理由。
4. 内部浏览次数。
5. eHunt 热度。
6. eHunt 增长率。
7. 适用品类或使用场景。

## 12. 接口设计要求

接口设计原则：

1. 接口统一使用 RESTful 风格。
2. 返回结构统一包含 code、message、data、traceId。
3. 分页接口统一包含 pageNum、pageSize、total、list。
4. 所有接口需要进行登录态校验。
5. 涉及业务数据的接口需要进行数据权限过滤。
6. 重要接口需要记录操作日志。

## 13. 非功能需求

### 13.1 性能要求

1. 首页核心指标接口 P95 响应时间小于 500ms。
2. 订单查询接口 P95 响应时间小于 500ms。
3. 关键词洞察接口 P95 响应时间小于 500ms。
4. 常规分析接口 P95 响应时间小于 800ms。
5. 大数据量查询需使用分页、索引、缓存和预聚合。
6. 高频接口应支持缓存策略，避免重复计算。
7. 图表接口应按页面需要返回数据，避免一次性返回过多明细。

### 13.2 安全要求

1. 密码必须加密存储。
2. 登录接口需要防暴力破解。
3. 接口需要进行身份认证和权限校验。
4. 数据导出需要权限控制。
5. 敏感操作需要记录操作日志。
6. 防止 SQL 注入、XSS、CSRF 等常见安全风险。
7. 后端需要限制用户只能访问其授权范围内的数据。

### 13.3 稳定性要求

1. 数据源异常时，系统需要返回友好的错误提示。
2. 查询超时时需要有明确提示和日志记录。
3. 服务异常需要记录错误日志。
4. 关键服务需要支持健康检查。
5. 指标聚合失败时不影响其他页面的基础查询。
6. eHunt 数据暂时不可用时，内部关键词浏览统计仍需正常展示。
7. 推荐关键词计算失败时，页面需展示空状态或最近一次可用推荐结果。

### 13.4 可维护性要求

1. 代码结构清晰，模块边界明确。
2. 业务指标口径需要有统一配置或文档说明。
3. 数据源适配逻辑需要独立封装。
4. 日志需要包含 traceId，方便问题定位。
5. 系统配置需要支持按环境区分，例如开发、测试、生产。

## 14. 验收标准

### 14.1 看板验收

1. 首页能展示总销售额、总订单量、客单价、退款率、同比、环比。
2. 指标数据与后端统计结果一致。
3. Top10 商品图表展示正确。
4. 月度趋势图支持今年与去年同期对比。
5. 筛选条件生效后，所有图表和指标同步刷新。
6. 数据源异常时，页面能展示明确提示。
7. 原“数据质量雷达”区域已调整为关键词搜索浏览洞察模块。
8. 输入或选择关键词“玉”时，系统能根据后台关键词统计数据展示对应浏览次数。
9. 关键词洞察模块下方能展示 eHunt 关键词趋势图和增长率较高的关键词列表。
10. eHunt 趋势模块下方能展示推荐关键词，并给出推荐理由。
11. 点击 Top10 商品排行中的任一商品时，右侧关键词搜索浏览洞察模块需要切换为该商品对应的关键词数据。
12. 点击 Top10 商品饼图中的任一扇区时，右侧关键词搜索浏览洞察模块需要切换为该商品对应的关键词数据。
13. 点击商品后，下方高增长关键词列表需要同步切换为当前商品对应的高增长关键词。
14. 点击商品后，推荐关键词模块需要同步切换为当前商品对应的推荐关键词。
15. 当前选中商品需要有明确高亮状态，右侧模块需要展示当前商品名称。

### 14.2 查询分析验收

1. 商品分析支持筛选、排序、分页和导出。
2. 区域分析支持区域下钻。
3. 时间趋势支持日、周、月、季度、年切换。
4. 订单查询支持多条件组合查询。
5. 图表支持导出 PNG。

### 14.3 关键词洞察验收

1. 支持按关键词、时间范围、店铺、业务线、品类筛选数据。
2. 支持按商品名称或商品编码筛选关键词数据。
3. 支持展示当前商品下关键词浏览次数、搜索次数、浏览占比和环比增长率。
4. 支持当前商品下的关键词浏览次数排行。
5. 支持展示 eHunt 关键词热度趋势。
6. 支持展示当前商品下增长率较高的关键词。
7. 支持商品切换后关键词排行和高增长关键词同步刷新。
8. 支持商品切换后推荐关键词同步刷新。
9. 支持展示推荐关键词、推荐分和推荐理由。
10. 当 eHunt 数据异常时，内部关键词浏览数据仍能正常显示。
11. 当商品或关键词没有数据时，页面展示空状态并推荐热门关键词。

### 14.4 权限验收

1. 不同角色登录后看到的菜单不同。
2. 无权限用户无法访问受限接口。
3. 数据权限能按业务线、店铺或区域生效。
4. 导出、查看详情、系统配置等操作受按钮权限控制。

### 14.5 性能验收

1. 首页核心接口 P95 响应时间小于 500ms。
2. 订单查询接口 P95 响应时间小于 500ms。
3. 关键词洞察接口 P95 响应时间小于 500ms。
4. 常规分析接口 P95 响应时间小于 800ms。
5. 大数据量列表查询支持分页，页面不会明显卡顿。

## 16. 一句话总结

本项目不是数据导入工具，也不是单纯的图表页面，而是一套基于企业已有业务数据和关键词趋势数据建设的经营统计分析平台。它的核心价值在于通过统一指标口径、权限控制、可视化分析、关键词洞察、全局搜索和智能问答，让企业已有数据变得可查询、可分析、可追溯，并辅助运营选词和经营决策。
