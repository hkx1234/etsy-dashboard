4.前端代码怎么学技术？
    1.前端，我个人觉得看懂+能够增改以及逻辑方面能够跑通就好

    标准:
        看得懂：知道文件之间怎么连起来
        改得动：知道改哪里、会影响哪里
        加得上：能新增功能，并和原架构保持一致
        调得出：出错时能定位问题
        说得清：能用自己的话解释数据流和组件关系
        接得上：能把 mock 数据换成接口数据
        维护得住：别人接手也能看懂
    且
        这个页面为什么这样拆
        这个数据为什么放这里
        这个状态为什么用 ref
        这个值为什么用 computed
        这个样式为什么写在 index.css
        这个路由为什么放在 router/index.ts


    2.改是怎么改？才算会？
        1.一个个函数，我去改了函数名，那么报错了，我是否能够知道逻辑是哪里出错？

        解:
            先找一个功能
            再找它对应的变量、函数、模板
            然后做一个小修改
            最后观察页面变化
        例:
            1. 找 MainLayout.vue 里的 a-menu
            2. 找 handleMenuClick
            3. 找 router/index.ts
            4. 新增一个菜单项
            5. 新增一个路由
            6. 看点击后是否能跳转

        2.css样式我想改变颜色，我是否知道在哪里？

        解:
            我知道这个颜色来自哪里
            是全局 CSS？
            是 Ant Design Vue 主题？
            是组件自带样式？
            是 ECharts 配置？
            还是内联 style？
        例:
            App.vue：Ant Design 主题色
            index.css：页面布局和卡片颜色
            Dashboard.vue：ECharts 图表颜色
            Analysis.vue：ECharts 图表颜色
            KeywordInsight.vue：ECharts 图表颜色
        

    3.增是怎么增。
        1.首先，比如是一个新的功能，实在不会，我依旧觉得可以问ai，但是如果下一次出现了还是相似的功能，就是自己要会去写，却，ai写下来的，必须是自己去理解逻辑是怎么写，为什么这么写，如果是一个在原本的代码上加一些额外的功能也跟新增功能类似。

        解:    
            第一次：让 AI 写，但要求它解释文件改动
            第二次：你照着写，AI 只检查
            第三次：你自己写，AI 只做 code review
            第四次：你能告诉别人为什么这么写
        项目:
            第一次：让 AI 帮你加一个“订单查询”页面
            第二次：你自己模仿加一个“用户管理”页面
            第三次：你自己加菜单、路由、页面、mock 数据
            第四次：你解释 MainLayout、router、pages 之间的关系




## AI 写的前端代码怎么学习

1. 先写清楚业务需求
   不只写功能，还要写页面、数据、用户操作、哪些做、哪些不做。

2. 不让 AI 一次性做完整系统
   按阶段来：页面原型、路由布局、mock 数据、接口接入、异常处理、组件优化。

3. 先验收页面，再阅读代码
   页面是否符合需求是一层，代码是否方便维护是第二层。

4. 阅读代码按顺序来
   package.json
   main.ts
   App.vue
   router/index.ts
   MainLayout.vue
   pages 页面
   mockData.ts
   index.css

5. 学前端不是死记代码
   要看懂文件关系、数据流、组件关系、路由关系、用户操作后的变化。

6. 修改练习要有目标
   比如改平台名称、改主题色、加菜单、加页面、加一个 KPI 卡片、加一个图表。

7. 新增功能可以先问 AI
   但下一次相似功能要自己能写出来，并且能解释为什么这么写。

8. 判断自己是否学会
   能自己改、能自己加、能自己调错、能自己解释、能把 mock 数据换成接口数据。
